# Review intake and mask-revision planning

The portable diagnostic scene is now a reusable input to human review intake. A completed, correctly bound JSON record can update readiness and produce planning inputs without running any models or rerunning the scene reconstruction. With no record, intake remains pending. Drafts, mismatched evidence and forbidden acceptance fields are refused before output creation.

`tools/tracehoi/intake_mask_review.py import --package PACKAGE --package-sha256 SHA256 --case alapuse02v3n60 --purpose review_intake --record REVIEW.json --output NEW_DIRECTORY` creates an immutable intake. Omit `--record` only to record a pending state, or to retain a completed record already embedded in the package. Existing output directories are refused. Original JSON bytes are saved as `review_original.json`; record timestamps and authorship remain self-reported.

Use the printed receipt binding with the same command's `verify` action and `--receipt-sha256 SHA256` to verify a relocated intake against the original package. Verification checks the complete diagnostic package, exact file inventory and hashes, then rebuilds readiness and any plan from the original record.

A completed `needs_revision` record produces `revision_plan.json` with exact regions and notes. `uncertain` routes to uncertainty resolution; `visually_consistent` routes to independent mask validation. None of these decisions edits pixels or certifies mask accuracy, scale, geometric accuracy, physical contact or placement. All diagnostic candidates and source meshes remain unchanged.

The offline intake dashboard shows the original image, provisional hand support and recorded regions. It links to the unchanged review form. Browser controls change the display only; the server CLI is authoritative for validation. Human observations are never generated by this tool.

Validation covers pending/completed intake, evidence mismatches, draft refusal, byte preservation, revision planning, inherited records, tampering, relocation and purpose restrictions. Integration additionally checks the real B4 package and normal Git publication. B4 was published as `fde85a72a577b18c4a33591454119a80f26ac936`; its recorded review state was missing.
