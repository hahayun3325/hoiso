# Portable TraceHOI proximity workspace — 2026-10-17

K4 published surface-coverage diagnostics at commit 12e17db0821ce8626cc2f3d3262870869c39026b. Its returned ZIP, terminal and five companion outputs verified. Comparing the exact server result with the Mac preview found 2,411 last-bit differences confined to per-face lower/upper distance bounds; the maximum absolute difference was 5.551115123125783e-17. All profile classifications, areas, centroids, witnesses and other report fields were identical. This exposed a portability limitation in K4's byte-for-byte recomputation check, not a change to the authenticated server files.

The new proximity pipeline connects the saved scene, J3 vertex-distance packet and K4 surface-coverage packet into one offline workspace. It preserves original viewer bytes and source evidence. The package contains a dashboard, the scene/vertex/coverage viewers, the independent-reference annotator, the original mask-review form required by the scene link, a summary, instructions and an exact file manifest. Extract the whole package and open index.html.

Verification first checks the supplied exact receipt SHA-256 and every source-file hash. It recomputes K4 from the hash-bound workspace and J3 evidence. Only `candidates/*/faces/*/{lower,upper}` may differ numerically, by at most `min(32 * ulp(max(1, object_bbox_diagonal)), numerical_guard / 1024)`. All non-endpoint fields, types, indices, hashes, witness coordinates, area values, profile counts and acceptance flags remain exact. Every face must retain its classification at every saved profile threshold. The saved HTML is rebuilt from the verified saved report and exact recomputed geometry, so the tolerance cannot admit arbitrary viewer code. No input bytes are rewritten or rounded.

Per-host difference counts are returned as a verification audit; they are not stored as mutable facts in the portable workspace. Workspace verification can therefore reproduce the same output bytes on the tested Mac and server arithmetic variants. This is narrow numerical compatibility, not permission to ignore source hash mismatches or a general tolerance for future algorithm changes.

The workspace displays four unchanged hypotheses without ranking or selecting one. It keeps the blocked transverse-crossing gate on the minimum-scale branch. Unsigned distances and area bounds do not establish contact, penetration depth or metric scale. Human visual review is complete; an independent mask reference remains absent. Mask accuracy, scale, placement and full parent acceptance remain false.

The CLI `tools/tracehoi/run_proximity_pipeline.py` supports `build` and `verify`. Both require workspace, distances and coverage directories with their exact receipt hashes, case ID, output directory and `--purpose proximity_pipeline`. Verification also requires the output receipt hash. No model, native import, GPU, fitting, mask editing or installation is involved.

The 29 new tests cover last-bit differences, larger perturbations, nonfinite and type changes, altered bindings, witnesses, area values, classifications and approval flags; purpose refusal; HTML escaping and companion links. Integration checks use the actual returned Linux coverage packet, verify source immutability and companion-viewer equality, and exercise publication, relocation, tampering, safe retirement and collection. The prior 199 tests remain part of publication validation.
